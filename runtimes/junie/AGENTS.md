# AGENTS.md — JDI workflow (Junie)

This project uses **JDI (Just Do It)** as its development workflow — a lean,
file-based loop with per-project specialists and hard quality gates.

## The loop

```
/jdi-new "<description>"   -> research + PROJECT.md + ROADMAP.md  (--auto = zero questions)
/jdi-bootstrap             -> generates the project's doer + reviewer specialists
/jdi-next                  -> derives where the phase is and runs the correct next step
```

Fine-grained commands (all available as skills — type the command in your
message, e.g. "/jdi-do board-cards"): `/jdi-discuss`, `/jdi-plan`, `/jdi-do`,
`/jdi-verify`, `/jdi-confirm-dod`, `/jdi-ship` (`--pr` opens a pull request),
`/jdi-loop` (bounded auto-iterate), `/jdi-issue` (autonomous card → PR),
`/jdi-status`, `/jdi-add-phase`, `/jdi-remove-phase`, `/jdi-migrate-phases`.

## How JDI maps to Junie

- **Commands are skills** (`.junie/skills/jdi-*/SKILL.md`) — Junie discovers
  them semantically from your message. Mention the command name and the phase
  slug in the same message ("run /jdi-plan for auth-flow").
- **Core agents are subagents** (`.junie/agents/jdi-*.md`) — Junie delegates
  to them automatically when a skill's process says "spawn jdi-planner" etc.
  Tool allowlists are enforced by Junie (the reviewer is genuinely read-only).
- **Per-project specialists** generated by `/jdi-bootstrap` live in
  `.jdi/agents/`. For Junie to delegate to them, copy them into
  `.junie/agents/` (or re-run `jdi install junie` after bootstrap).

## State (never edit runtimes by hand)

All state lives in `.jdi/` — PROJECT.md (locked), ROADMAP.md (no status
lines), DECISIONS.md (append-only), phases/<slug>/ artifacts. Phase status is
DERIVED from artifacts (SHIPPED.md → done, REVIEW.md → verified, SUMMARY.md →
executed, PLAN.md → planned, CONTEXT.md → discussed). STATE.md is an untracked
advisory cache.

Rules: Conventional Commits (scope = phase slug) · 1 task = 1 atomic commit ·
never `--no-verify` · locked decisions never reverse (the reviewer blocks
contradictions) · Security > Performance > Best Practices.
